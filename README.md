# 任务矩阵 TASK//MATRIX

常驻 Windows 任务栏的四象限（艾森豪威尔矩阵）计划工具，电子工业风。

## 下载哪个

| 文件 | 说明 |
|---|---|
| `TaskMatrix-Setup-1.0.0.exe` | 安装版（推荐）。可选安装位置，自动创建桌面和开始菜单快捷方式，可在系统设置里卸载 |
| `TaskMatrix-1.0.0-免安装版.zip` | 免安装版。解压到任意文件夹，运行里面的 `任务矩阵.exe` 即可；不想用了直接删文件夹 |

两个版本的任务数据是共用的，存放在 `%APPDATA%\任务矩阵\data.json`，换版本或重装都不会丢。

> 程序没有做代码签名，第一次运行时 Windows SmartScreen 可能提示"已保护你的电脑"，点 **更多信息 → 仍要运行** 即可。

## 系统要求

- Windows 11 x64（Windows 10 大概率也能用，未专门测试）
- 任务栏在上 / 下 / 左 / 右都支持，包括 StartAllBack 等第三方任务栏

## 怎么用

- **呼出面板**：点托盘的四色方块图标，或按 `Alt+Shift+Q`
- **添加任务**：输入后回车；`Tab` / `Ctrl+1~4` 选象限
- **完成任务**：点任务左边的方块（有音效、粒子和经验值反馈，10 秒内连续完成有连击）
- **编辑 / 换象限**：双击文字编辑；拖到别的象限
- **右键托盘图标**：小组件开关、钉住面板、音效、开机自启、主题 / 皮肤 / 圆角、退出

## 任务栏小组件

任务直接显示在任务栏的空白处，不需要打开面板：

- **形态随空白自动变化**：空白够宽时展开成任务卡片；窄一点显示"有任务的象限计数 + 最该做的一条"；再窄折叠成一个数字徽标（可改成直接隐藏）。开新应用图标变多时会自动让位，不会压住任何图标和托盘。
- **勾选方块**直接完成任务。
- **点任务文字**（或象限计数块）会下拉出同颜色的全部任务，选一条就把它换到任务栏上显示（固定在最前）；列表里也可以直接 ✓ 完成，或点"恢复自动顺序"。
- **自动轮换**（默认关）：开启后任务栏上显示的任务按间隔自动换；鼠标停在小组件上、或刚手动选过任务时会暂停。
- 没有任务的象限，对应颜色块不显示。
- **右键**任务卡片可以完成 / 编辑 / 换象限 / 删除；右键空白处出主菜单。
- 全屏游戏 / 视频 / 演示时自动隐藏；任务栏设为"自动隐藏"时可选跟随弹出或不显示。

支持的任务栏排布：

| 任务栏 | 说明 |
|---|---|
| 经典任务栏（StartAllBack、ExplorerPatcher 等） | 通过辅助功能接口精确读取每个图标的位置 |
| 原版 Win11 任务栏（居左 / 居中） | 通过 UI Automation 读取；居中时左右各有一块空白，可选放哪一侧。**此路径目前只做了单元测试和接口验证，缺少原版任务栏上的实机验证** |
| 读不到图标位置时 | 退回紧凑形态，可以在任务栏上拖动小组件 |

小组件的参数在面板右上角 `BAR` 里调：放在哪块空白、与图标的间距、最大宽度、空间不足时折叠还是隐藏、任务栏自动隐藏时的行为、自动轮换及间隔。

## 主题、皮肤与圆角

- **主题**（配色）：钢铁灰、冷却液、警戒黄、铝板
- **皮肤**（UI 风格）：极简（默认）、工业、战术 HUD
- **圆角**：极简皮肤下可调 0–20px（0 = 直角），面板、小组件、菜单同步生效

三者可任意组合，在面板右上角 `SKN` 或托盘右键菜单里切换。

## 从源码构建

```bash
npm install
npm start          # 开发运行
npm test           # 任务栏布局算法的单元测试
npm run dist       # 打包到 dist/
```

自定义主题/皮肤：见 `renderer/themes.js` 顶部注释。

### 开发测试工具

`dev-tools.js` 是只给开发用的测试工具（不会打进安装包）：在真实桌面上模拟点击、截屏、压测，用来复现和验证只在真实环境才出现的问题。通过环境变量启用：

| 变量 | 作用 |
|---|---|
| `TM_USERDATA=目录` | 把数据目录指到别处，测试时不碰真实任务 |
| `TM_SNAPSHOT=目录` | 截取面板 / 小组件 / 菜单并检查菜单反复开关 |
| `TM_STRESS=panel\|widget` | 压测：面板反复显示是否出现空白；任务栏盖住小组件后多久被提回 |
| `TM_PICKTEST=1` | 功能测试：空象限、同色下拉、替换显示、轮换（需 `TM_PICKTEST_DIR`） |
| `TM_FAKE_SPACE='[[0,48],[800,1128],[1500,1920]]'` | 伪造任务栏的占用区间（物理像素），在真机上预览别的任务栏排布 |
| `TM_DEBUG_WIDGET=1` | 打印小组件显示 / 隐藏 / 布局 / 点击的时间点和原因 |
| `TM_DEBUG_PANEL=1` | 打印面板的显示 / 隐藏 / 焦点事件和"画出来"的耗时 |
| `TM_AUTOHIDE=1` | 面板每次显示 2 秒后自动收起，配合 `TM_RECTS_FILE` 用真实鼠标反复点击测试 |
| `TM_RECTS_FILE=文件` | 每 0.4 秒把小组件各可点击元素的屏幕坐标写进文件 |
| `TM_HANGTEST=1` | 人为卡死面板页面，检查任务栏上的操作能否恢复生效 |
| `TM_BLOCKTEST=文件` | 面板显示的同时堵死主进程，观察系统的"未响应"幽灵窗口 |
| `TM_GPUTEST=文件`（`TM_GPUMODE`、`TM_GPUDIAG`） | 杀掉 GPU 进程或面板页面进程，观察窗口会变成什么样 |
| `TM_DIAG=1` | 正常状态下保存一份诊断快照并检查内容 |
| `TM_NO_WATCH=1` | 关闭"页面崩溃自动重载"，测试时保留崩溃后的原样 |

## 排查"面板黑屏 / 点击没反应"

程序会把少见的异常记在 `%APPDATA%\任务矩阵\`：

- `debug.log`：面板显示后没有画出来、页面崩溃或无响应、GPU 进程退出、睡眠 / 唤醒 / 锁屏、显示器变化，都带时间。
- `diagnose.log`：上述异常发生时**自动**保存的诊断快照；也可以在托盘右键菜单里点 **保存诊断信息** 手动保存（看到黑屏时点一下最有用）。快照包含：页面进程能否响应一帧、Chromium 认为面板上画的是什么（对比屏幕上实际看到的，可分清是页面问题还是系统合成问题）、GPU 与显示器状态、各进程状态、电源状态。

遇到问题时把这两个文件发给开发者即可。
